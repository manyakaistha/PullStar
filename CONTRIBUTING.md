# Contributing to PullStar

Open an issue with the problem, expected result, and reproduction steps before proposing a large change. Include your operating system, PullStar version, input format, and relevant settings. Use synthetic or explicitly shareable images; do not upload private photos or credentials.

Follow the source setup in the README. Keep processing outside the renderer and keep long-running work cancellable. Add a regression test when fixing processing, export, or lifecycle behavior. Run Python tests, frontend tests, lint, and the production build before submitting a pull request.

Pull requests should explain the user-visible behavior, why it changed, and how it was verified. The original application currently has no open-source license. Discuss contribution and licensing terms with the maintainer before submitting code.
